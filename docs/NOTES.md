# Atomix Demo · 说明文档

## 一、实现思路与关键取舍

### 1. 核心思路

Atoms 的本质是「把一次软件构建过程透明地交给 Agent 完成」。本 Demo 复刻的不是界面壳子，而是一条**真正的 ReAct Agent 循环**：

```
用户输入需求 → think（分析现状，决定下一步）
            → act（调用工具：plan_app / write_file / read_file / run_checks / finish）
            → observe（工具真实执行，观察结果回喂模型）
            → 循环往复，直到产物通过校验后 finish
```

- **模型侧**：live 模式走 DeepSeek function calling 多轮循环（每轮 think→act→observe，上限 12 轮）；demo 模式以脚本化轨迹驱动**同一套真实工具执行器**（无 Key 也能完整观察闭环）。
- **工具侧**：`run_checks` 不是装饰——它对产物执行 6 项真实静态校验（文档结构、闭合、交互脚本、持久化调用、`document.cookie` 沙箱兼容性、体积），发现问题回喂模型触发**真实自修复**（最多 3 轮）；demo 轨迹里就演示了一次"校验抓出沙箱兼容性问题 → 定位修复 → 重写复检通过"。
- **任务侧**：全新构建与**迭代修改**（`POST /api/projects/:id/refine`，"把标题改成深色"式追问）走同一个 ReAct 循环，迭代时先 `read_file` 读旧产物再最小化修改。

全程通过 **SSE 流式推送**到前端时间线（🧠 思考 / ⚡ 行动 / 👁 观察 三类事件实时落库），历史回看可完整回放 Agent 的每一步——这对应「工程师由团队端到端发现问题、解决问题」的过程可视化。

### 2. 关键取舍

**取舍一：受约束的生成空间，换取 100% 可运行率。**
没有做完全自由的世界级代码生成，而是让 Agent 在三个精心打磨的内置模板（待办清单 / 便签墙 / 看板）中做语义选择，再按模板能力清单生成代码。产物永远真实可交互、数据可持久化、刷新不丢。这是对「可交付性 > 概念验证」的直接回应：6-8 小时内，稳定性优先于自由度。live 模式下 LLM 输出异常时自动回退模板兜底，任何情况下用户都能拿到可运行的应用。

**取舍二：单文件 HTML 产物 + 沙箱 iframe。**
生成产物不落盘为项目文件树，而是一个完整 HTML 文档（可用 Tailwind CDN），通过 `sandbox="allow-scripts allow-forms allow-modals"` 的 iframe 渲染，与应用工作台物理隔离。好处：天然安全（无同源权限）、零构建依赖、新窗口打开即独立应用。代价：不支持多文件工程。这是刻意的范围控制。

**取舍三：Go + Vue 全栈单仓库。**
贴合岗位 JD 的技术栈（Vue Web + Go 后端），前后端一个仓库、一条命令起服务。SSE 替代 WebSocket：单向进度推送场景下更简单可靠，无需额外依赖。

**取舍四：演示模式一等公民。**
`DEEPSEEK_API_KEY` 未配置时不是报错，而是自动降级到「规则引擎规划 + 内置模板生成」，完整走完五阶段流水线。评审者无需任何 Key 即可体验全部交互；配置 Key 后同一套代码切换为真实 LLM 生成。部署稳定性和演示一致性同时得到保证。

### 3. 工程决策

- **鉴权**：JWT（7 天）+ bcrypt 密码哈希；EventSource 无法带 Header，SSE 端点支持查询参数传 token 的回退。
- **数据模型**：`users` / `projects` / `events` 三表。生成产物 HTML 与执行事件全部入库，刷新、重启、换设备登录均可回放完整历史。
- **错误处理**：LLM 超时/异常 → 模板兜底；产物缺 HTML 结构 → 校验阶段回退；前端 SSE 断开 → 状态复位可重试。

## 二、当前完成程度

**已完成：**

- 注册 / 登录 / 登出，JWT 鉴权全链路
- **ReAct Agent 循环**：think→act→observe 工具循环（DeepSeek function calling），5 个真实工具 + 6 项静态校验驱动的自修复闭环，上限 12 轮 / 3 轮自动修复
- **迭代修改**：在已有项目上追加自然语言修改指令（refine 走同一 ReAct 循环，先读旧产物再最小化修改）
- 自然语言需求输入 → SSE 实时时间线（阶段进度 + 🧠思考/⚡行动/👁观察 轨迹事件，实时落库可回放）
- 三个内置应用模板（真实交互 + localStorage 持久化），live / demo 双模式同构切换
- 沙箱 iframe 实时预览（含存储垫片，沙箱内数据操作刷新不丢）+ 新窗口独立打开
- 项目历史持久化与回看（含完整 Agent 执行轨迹回放）
- 生产构建方案（前端 build 产物由 Go 静态托管，单二进制部署）

**未完成 / 已知限制：**

- 单文件产物，不支持多文件工程与真实后端注入
- 工具集为单文件应用场景定制（无 shell/npm 等通用工具），ReAct 循环的通用化留作扩展
- 无自动化测试（以手工端到端验证代替）
- JWT 密钥默认内置，生产部署需通过环境变量覆盖

## 三、如果继续投入时间

按优先级：

1. **产物落盘为真实工程（P0）**：write_file 支持多文件写入，生成 Vite 项目结构而非单文件，支持导出 zip / 推送 GitHub（Atoms 的 GitHub Sync 对应物）——ReAct 循环与工具注册表已为多文件天然就绪。
2. **token 级流式输出（P0.5）**：think 与代码生成改为 streaming，时间线逐字渲染。
3. **通用工具集（P1）**：bash / grep / edit 等通用工具接入同一循环，从"应用构建 Agent"走向"通用编码 Agent"。
4. **多 Agent 并行（P1）**：规划、构建、评审拆为独立 Agent 角色，模拟 Atoms 的「AI 员工团队」，含 Agent 间消息总线。
5. **Race Mode（P1）**：同一需求并行跑多个模型/温度，产出多版本供用户择优——直接对标 Atoms 的差异化特性。
6. **一键部署（P2）**：生成的应用直接发布为独立公网 URL，附访问统计。
7. **自动化测试（P2）**：为 ReAct 循环补集成测试（SSE 事件序列断言、工具调用轨迹快照、校验器单测）。
