# Atomix Demo · 说明文档

## 一、实现思路与关键取舍

### 1. 核心思路

Atoms 的本质是「把一次软件构建过程透明地交给 Agent 完成」。本 Demo 复刻的不是界面壳子，而是这条**端到端流水线**：

```
用户输入需求 → Agent 规划（理解需求、选定模板、输出步骤）
            → 构建（生成完整单文件应用代码）
            → 运行（启动沙箱预览环境）
            → 校验（产物完整性检查，异常回退兜底）
            → 完成（持久化入库，前端实时预览）
```

全程通过 **SSE 流式推送**到前端时间线，用户看到的是 Agent「怎么想、怎么建、怎么验」，而非黑盒等待——这对应笔试题眼中「工程师由团队端到端发现问题、解决问题」的过程可视化。

### 2. 关键取舍

**取舍一：受约束的生成空间，换取 100% 可运行率。**
没有做完全自由的世界级代码生成，而是让 Agent 在三个精心打磨的内置模板（待办清单 / 便签墙 / 看板）中做语义选择，再按模板能力清单生成代码。产物永远真实可交互、数据可持久化、刷新不丢。这是对「可交付性 > 概念验证」的直接回应：6-8 小时内，稳定性优先于自由度。live 模式下 LLM 输出异常时自动回退模板兜底，任何情况下用户都能拿到可运行的应用。

**取舍二：单文件 HTML 产物 + 沙箱 iframe。**
生成产物不落盘为项目文件树，而是一个完整 HTML 文档（可用 Tailwind CDN），通过 `sandbox="allow-scripts allow-forms allow-modals"` 的 iframe 渲染，与应用工作台物理隔离。好处：天然安全（无同源权限）、零构建依赖、新窗口打开即独立应用。代价：不支持多文件工程。这是刻意的范围控制。

**取舍三：Go + Vue 全栈单仓库。**
贴合岗位 JD 的技术栈（Vue Web + Go 后端），前后端一个仓库、一条命令起服务。SSE 替代 WebSocket：单向进度推送场景下更简单可靠，无需额外依赖。

**取舍四：演示模式一等公民。**
`DEEPSEEK_API_KEY` 未配置时不是报错，而是自动降级到「规则引擎规划 + 内置模板生成」，完整走完五阶段流水线。评审者无需任何 Key 即可体验全部交互；配置 Key 后同一套代码切换为真实 LLM 生成。部署稳定性和演示一致性同时得到保证。

### 3. 工程决策

- **鉴权**：JWT（7 天）+ bcrypt 密码哈希；EventSource 无法带 Header，SSE 端点支持查询参数传 token 的回退。
- **数据模型**：`users` / `projects` / `events` 三表。生成产物 HTML 与执行事件全部入库，刷新、重启、换设备登录均可回放完整历史。
- **错误处理**：LLM 超时/异常 → 模板兜底；产物缺 HTML 结构 → 校验阶段回退；前端 SSE 断开 → 状态复位可重试。

## 二、当前完成程度

**已完成：**

- 注册 / 登录 / 登出，JWT 鉴权全链路
- 自然语言需求输入 → Agent 五阶段流水线 → SSE 实时时间线（阶段进度 + 逐条事件）
- 三个内置应用模板（真实交互 + localStorage 持久化），语义匹配选择
- live / demo 双模式，DeepSeek 集成（计划生成 + 代码生成，输出解析与兜底）
- 沙箱 iframe 实时预览 + 新窗口独立打开
- 项目历史持久化与回看（含历史事件回放）
- 生产构建方案（前端 build 产物由 Go 静态托管，单二进制部署）

**未完成 / 已知限制：**

- 生成应用暂不支持增量修改迭代（重新输入需求即重新生成）
- 单文件产物，不支持多文件工程与真实后端注入
- 无自动化测试（以手工端到端验证代替）
- JWT 密钥默认内置，生产部署需通过环境变量覆盖

## 三、如果继续投入时间

按优先级：

1. **迭代修改（P0）**：在现有项目上追加自然语言修改指令，Agent 做 diff 式更新而不是全量重生成。这是从「生成工具」到「协作平台」的关键一步，也是 Atoms 的核心体验。
2. **产物落盘为真实工程（P0.5）**：生成 Vite 项目结构而非单文件，支持导出 zip / 推送 GitHub（Atoms 的 GitHub Sync 对应物）。
3. **多 Agent 并行（P1）**：规划、构建、评审拆为独立 Agent 角色，模拟 Atoms 的「AI 员工团队」，含 Agent 间消息总线。
4. **Race Mode（P1）**：同一需求并行跑多个模型/温度，产出多版本供用户择优——直接对标 Atoms 的差异化特性。
5. **一键部署（P2）**：生成的应用直接发布为独立公网 URL，附访问统计。
6. **自动化测试（P2）**：为流水线补集成测试（SSE 事件序列断言、模板产物快照）。
